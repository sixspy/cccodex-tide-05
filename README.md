# 潮位报文归集台

港务水文组收到各潮位站的定长报文。归集员把一批报文贴进来，系统先按站码和时刻解析，**落库前完成批内去重**；能落库的写入归集表，列数不对、站码坏了、批内重行或时刻已经存在的行单独列出。

## 核心规则

### 批内重行与两种取舍

同一批里两行**站码和观测时刻都相同**即为重行，去重在落库前完成。取舍只有两种，写进当日策略簿后**当日禁止改口**：

| 取舍 | 行为 |
|------|------|
| 留行 | 只留行号更小的一行入库，其余行进跳过队列（注明保留行号） |
| 双拒 | 同一重行组里每一行都不入库，全部进跳过队列 |

- 批内设置可在「待比较」阶段修改；一旦点了「开始比较并落库」进入比较中，设置立即冻结。
- 批次的批内取舍与当日策略簿不一致时，批次标注**批内取舍不符**。
- **行号缺失的行不参与重行比较**。

### 顺序锁

左右两侧若同时提交含同一对重行的批次：比较事务对每个重行键（站码+时刻）加事务级咨询锁串行化，`order_locks` 台账持久记录先到批次。顺序锁只放行先到的一批，后到的一批**整批拦截**（状态「顺序锁拦截」，一行不落）。被拦批次在拦截键之前抢占的其它键会撤回，不留幻影锁。

### 两阶段流程

1. **贴入解析**：批次停在「待比较」，逐行写入 `batch_rows`，不碰归集表，可改批内设置。
2. **开始比较并落库**：批内去重 → 顺序锁 → 跨批去重 → 写 `landed_rows`，一个事务完成。

## 报文格式

每行四段，竖线分开：`站码|十二位时间|潮位厘米|质量旗`，行号取物理行号。
也支持五段式，首段为显式行号；首段写 `-` 表示**行号缺失**，该行不参与重行比较：

```
BZ03|202611130900|176|A
12|BZ03|202611131000|165|M
-|BZ03|202611131100|160|A
```

质量旗 A 实测，M 插补，B 可疑。

## 接口一览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/POST | `/api/policy` | 当日策略簿；POST 写入后当日锁定 |
| GET | `/api/batches` | 批内列表：保留行号、跳过行号、取舍名 |
| POST | `/api/batches` | 贴入解析，批次进入「待比较」 |
| PUT | `/api/batches/{id}/decision` | 改批内设置（仅待比较阶段） |
| POST | `/api/batches/{id}/compare` | 开始比较并落库 |
| GET | `/api/batches/{id}` | 行号详情，含逐行去向、跳过原文、顺序锁 |
| GET | `/api/skips` | 全站跳过队列 |

## 数据表

| 表 | 作用 |
|----|------|
| `policy_book` | 每日一条策略簿，写入当日锁定 |
| `intake_batches` | 批次主表，含取舍、不符标记、顺序锁拦截标记 |
| `batch_rows` | 逐行解析结果与去向（留行/双拒/跳过/已落库/未比较…） |
| `landed_rows` | 已落库归集行，`(站码, 时刻)` 唯一 |
| `reject_rows` | 解析失败行 |
| `skip_queue` | 跳过队列，含原因、取舍名、保留行号、原文 |
| `order_locks` | 顺序锁台账，记录先到/被拦批次 |
